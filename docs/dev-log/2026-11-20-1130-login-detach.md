# login --detach: 링크만 찍고 끝나고, 로그인은 떨어져 나간 프로세스가 끝낸다

> 작성: 2026-11-20 11:30 KST · @agent

## What
`heyyumi login --detach`를 더했다(0.1.6). 바로 `{"ok":true,"pending":true,"url":...}`를 출력하고 끝난다. 그동안 따로 떨어져 나간 프로세스가 127.0.0.1 콜백을 최대 5분 동안 기다렸다가 로그인을 저장한다. 0.1.7에서는 `status`, `login_required`, 시간 초과 안내의 `next`를 `login --detach`로 바꿨다.

## Why
heyyumi.ai 홈에 "AI에 한 줄 붙여 넣기" 연결 안내를 넣었다. 에이전트는 로그인 링크를 사람에게 건네고 턴을 끝내야 한다. 그런데 Cursor 에이전트에서 시험해 보니, 셸 `&`나 `nohup`으로 띄운 로그인은 명령이 끝날 때 같이 꺼졌다. 사람이 링크를 눌러도 받을 쪽이 없었다. 이 맥에서 직접 재 보니 Node `spawn(..., { detached: true })`로 띄운 프로세스만 살아남았다.

## How
- `src/detach.js`: 같은 CLI를 `login --no-browser --timeout N --client-name NAME`로 떼어서 띄운다. 출력은 설정 폴더의 `login.log`(0600)에 쓴다. 그 파일에서 인증 URL이 나오면 바로 돌려준다. 자식이 먼저 끝나면 그 JSON(이미 로그인됨이거나 오류)을 돌려준다.
- 이미 로그인돼 있으면 부모가 먼저 `alreadySignedIn`으로 끝낸다(기존 동작 그대로).
- 사람이 터미널에서 쓰는 `login`(브라우저 자동 열기, 끝날 때까지 기다림)은 바꾸지 않았다.
